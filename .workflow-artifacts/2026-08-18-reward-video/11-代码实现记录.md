# 激励视频可插拔实现记录

## 实际修改范围

- `sdk`：增加激励视频 Provider 协议、注册表、默认 WebView Ability、slot `appId` 解析，以及穿山甲、优量汇、汇川三个实现。
- `demo`：验证三个广告 SDK 的传递依赖和 Manifest 合并。
- 根工程：增加汇川与穿山甲 Maven 仓库。

## 实施决策

- H5 固定调用 `hra.ad.showRewardedVideo`，不传 `slotId`。
- 核心按服务端 slot 顺序选择第一个已安装 Provider 可处理的配置。
- 汇川初始化使用 `rewardAdSlots[].appId`，不复用 Lamps appId，也不硬编码 heroes 的 appKey。
- 三个平台都放在 `sdk` 模块，通过类名反射延迟注册；宿主排除某个平台传递依赖后，不加载对应 Provider。
- SDK 和 Demo 的 `minSdk` 调整为 24，以满足当前穿山甲 `7.6.1.2` 的最低版本要求。
- 个性化广告开关默认关闭；当前需求没有提供隐私开关映射。

## 与方案一致性

- 三个平台均完成最小加载、展示、激励、关闭、错误和 15 秒加载超时链路。
- 已保留 heroes 的关键 H5 状态名称，移除 pid 接口请求、多 DSP 竞价、上报和预加载缓存。
- 未引入其他广告平台模块；后续平台可复用 `RewardAdProvider`。

## 后续修改：Channel SDK 初始化收口

- 在 `data/sdk/channel` 的 `TTSdkManager`、`YLHSdkManager`、`NoahSdkManager` 中分别实现平台初始化。
- 三个 Manager 统一接收广告平台专用的 `ThirdSdkInitCallback`，分别通过 `success()` 和 `fail(code, message)` 返回初始化结果，避免与 Lamps SDK 主初始化回调混用。
- 三个 Reward Provider 改为调用对应 Manager，移除 Provider 内重复的初始化配置。
- `:sdk:compileDebugKotlin` 与 `:demo:compileDebugKotlin` 验证通过。

## 后续修改：配置成功后的 SDK 初始化分发

- 新增 `data/sdk/init/ISdkInitProvider`，并实现穿山甲、优量汇、汇川三个 Provider。
- 新增 `SdkInitDispatcher`，按服务端 slot 配置选择已注册的 Provider。
- `AppInitDataLoader` 返回远端请求状态；远端配置成功后，`SdkRuntime` 等待已配置第三方 SDK 初始化完成再进入 Ready。
- Channel Manager 增加重复初始化保护，避免启动阶段初始化后在广告请求阶段再次初始化。
- `:sdk:assembleDebug` 与 `:demo:compileDebugKotlin` 验证通过。

## 后续修改：初始化 Provider 注册方式

- 移除 `SdkInitDispatcher` 中基于描述符和反射创建 Provider 的实现。
- Dispatcher 初始化时通过 `register()` 直接注册三个 `ISdkInitProvider`，并按实现类去重。
- 分发初始化前按 slot 的 `appId` 去重，避免同一广告 SDK 重复初始化。
- 任务构建与主线程分发从 `initSdk()` 拆分；单任务启动合并回 `dispatchTasks()`，通过轻量回调方法聚合完成状态，不保留额外 Coordinator 类型。
- `:sdk:compileDebugKotlin` 与 `:demo:compileDebugKotlin` 验证通过。

## 后续修改：Init Data 缓存优先策略

- 缓存解析且业务校验通过时，立即用于本次 SDK 初始化，并在工作线程异步请求远端刷新缓存。
- 缓存缺失、解析失败或业务校验失败时，同步等待远端数据；远端数据解析和业务校验均通过才算成功。
- 校验要求 token 非空、至少存在一个广告位，并且每个广告位的 appId、slotId 和渠道标识有效。
- 缓存命中后的远端刷新只更新缓存，不替换本次运行时配置，避免已初始化 SDK 与新 slot/appId 不一致。
- 无论有效数据来自缓存还是远端，都会继续执行第三方 SDK 初始化分发。
